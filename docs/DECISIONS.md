# Technical decisions

## Phase 1

### Replace the previous LangChain stack
Chose a from-scratch layout (FastAPI + psycopg 3 + sentence-transformers) and removed LangChain, FAISS, and Chroma.
Reason: the old schema and retrieval path cannot support per-model embedding tables, article-level metadata, or LangChain-free generation.
Rejected: keeping the old `rag_service.py` beside the new ingest pipeline (two sources of truth).

### Embedding tables named from the model slug
Chunks live in `chunks`; vectors live in `chunk_embeddings_<slug>` with HNSW cosine and a dimension taken from the loaded model.
Reason: Phase 5 must compare embedding models and chunk sets without rewriting one `VECTOR(384)` column.
Rejected: a single embedding column on `chunks`.

### OCR is per page, behind an `OcrEngine` protocol
Pages with too little text, replacement characters, or abnormal Vietnamese letter ratio are routed to OCR. Default engine is Tesseract (`vie`); if the binary is missing, the factory falls back to `none` and logs a warning.
Reason: mixed text/scan PDFs are common; later a VLM engine can implement the same protocol.
Rejected: OCR for the whole file, or a hard dependency that crashes ingest when Tesseract is absent.
Deskew is not implemented in Phase 1 (would need extra CV libraries); only grayscale is applied.

### Sentence chunking uses underthesea, with regex fallback
`underthesea.sent_tokenize` is the primary splitter for the `sentence` strategy.
Reason: it handles Vietnamese abbreviations better than splitting on `. `.
Rejected: `pyvi` for this step (it is word segmentation, not sentence splitting). BM25 tokenization is deferred to Phase 2.

### Recursive character splitter is in-repo
The `fixed` strategy copies the usual recursive-separator behavior without LangChain.
Reason: the stack forbids LangChain; eval must pin chunking behavior in this repository.

### Chat API removed until generation exists
`POST /api/v1/chat` from the previous demo is deleted in Phase 1.
Reason: it targeted a schema and pipeline that no longer exist. The static UIT UI remains but cannot answer yet.

## Phase 2 - Retrieval

### Indexed pgvector queries over full table scans
Dense retrieval relies strictly on `ORDER BY e.embedding <=> %s::vector LIMIT %s` using the HNSW index on `chunk_embeddings_<slug>`.
Reason: pulling entire tables into application memory breaks scalability and invalidates latency benchmarks in evaluation.

### BM25 index built once per chunk_set with underthesea tokenization
BM25Okapi is initialized lazily and cached per `chunk_set`, tokenized via `underthesea.word_tokenize(format="text")` with regex fallback.
Reason: compound Vietnamese words (e.g., `học_phần`, `khóa_luận`) score significantly more accurately under BM25 than unigram splits. An explicit `rebuild()` method is provided.

### RRF with k=60 and 20 candidates
Reciprocal Rank Fusion merges top-20 dense and top-20 BM25 candidate lists with smoothing parameter $k=60$.
Reason: Cormack et al. established $k=60$ as robust across diverse score distributions without needing score normalization.

### Lazy-loaded CrossEncoder reranker
`BAAI/bge-reranker-v2-m3` is loaded only on the first call to `rerank()` and can be toggled via `RERANKER_ENABLED`.
Reason: CrossEncoders are memory-heavy (~2.2GB) and slow on CPU; isolating the component allows fast unit testing and clean ablation comparison in Phase 5.

## Phase 3 - Generation & Guardrails

### Fast 4-intent routing with conversational query rewriting
Incoming queries are classified into `SMALL_TALK`, `UIT_REGULATION`, `OUT_OF_SCOPE`, or `AMBIGUOUS`.
For regulation queries, spoken phrasing (e.g., "em bị ốm nằm viện ko thi được") is rewritten into formal academic terminology ("quy định hoãn thi vắng thi lý do chính đáng ốm đau tai nạn điểm I") to bridge lexical mismatch in retrieval.
Reason: conversational Vietnamese vocabulary diverges drastically from formal university regulations; query rewriting dramatically lifts reranker confidence from ~0.05 to >0.85.

### Evidence Gate threshold before LLM synthesis
If the top retrieved chunk rerank score falls below `EVIDENCE_MIN_SCORE` (default 0.02) or no chunks exist, the pipeline short-circuits to a polite refusal directing the student to the Academic Affairs Office (Phòng Đào tạo).
Reason: LLMs hallucinate plausible-sounding rules when forced to answer from ungrounded context; halting early ensures 100% adherence to verified facts.

### Code-level citation validation over LLM trust
Every citation generated by the LLM (`source_file`, `article`, `page`, `quote`) is validated in Python against the retrieved candidate set. Ungrounded citations or hallucinated files are pruned automatically before returning to the user.
Reason: prompt engineering alone cannot guarantee zero citation hallucination; deterministic verification in application code enforces ground truth.

### Graceful degradation with extractive fallback
If the LLM endpoint is unreachable or times out, the system falls back to an extractive answer quoting the top retrieved chunk directly with its verified citation.
Reason: ensures zero service outages even if external LLM gateways experience downtime.
